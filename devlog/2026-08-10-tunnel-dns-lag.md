# 2026-08-10 トンネル URL は発行されたがブラウザで NXDOMAIN

5回目の実機実行。ポート 8081 への変更でセル5（Open WebUI 起動）を初めて通過。
セル6もトンネル URL の表示まで5秒で到達したが、ブラウザで開くと
`DNS_PROBE_FINISHED_NXDOMAIN`（名前解決できない）。

## 分析

cloudflared は Quick Tunnel の URL を**予約した時点で**ログに出す。実際に世界中の DNS から
引けるようになるまでには数十秒〜数分のラグがあり、その間にアクセスすると NXDOMAIN になる。
さらにクライアント OS が「存在しない」という否定応答をキャッシュするため、
反映後もしばらく開けないことがある（Windows は `ipconfig /flushdns` で解消）。

セル側の問題は「URL がログに現れた」ことを成功と見なしていたことで、
実際に通ることは確認していなかった。

## 対処

- `start_tunnel()` に**疎通確認**を追加: URL 取得後、公開 URL 経由の `/health` が
  200 を返すまで最大120秒待つ（Colab VM 側から確認する）。確認できて初めて成功として表示する
- 疎通しないまま時間切れになった URL は捨てて、トンネルごと取り直す（リトライ回数に含める）。
  リスク3のリトライがこれで「取得できたか」ではなく「使えるか」を基準に動くようになった
- URL 表示に「開けない場合は1〜2分待って再読み込み」の案内を追加

## 学び

- 「リソースの発行」と「リソースが使える」は別のイベント。成功判定は後者に置く
- ユーザー側のトラブルシュート手順（DNS フラッシュ等）は、必要になった時に案内するのではなく
  URL のすぐ横に出しておく

## 検証状況

- 疎通確認つきトンネル取得は実機未検証。次回実行で確認する
- なお今回の URL 自体は数分後に開けるようになった可能性が高い（ユーザーの再試行待ち）
