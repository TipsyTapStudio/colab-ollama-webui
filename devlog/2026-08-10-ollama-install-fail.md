# 2026-08-10 Colab 初実行: Ollama の install.sh が失敗

フェーズ1ノートブックの初の実機実行（人力検証）で、セル2の `curl -fsSL https://ollama.com/install.sh | sh` が exit 1 で失敗した。

## 事象

- セル2で RuntimeError。install.sh が終了コード1を返した
- **スクリプト自身のエラーメッセージがセル出力に一切残っておらず、失敗理由を特定できなかった**

## 原因分析

失敗の直接原因は不明のまま（出力が取れていないため）。ただし設計上の問題が2つあった。

1. `run()` がサブプロセスの出力表示を fd 継承まかせにしていた。Colab ではこれでサブプロセスの出力が表示されない（少なくとも今回のケースでは何も残らなかった）。**エラーが見えない構造は、失敗原因そのものより先に潰すべき問題**
2. install.sh は systemd・GPU ドライバ・ディストリビューション判定などの環境検査を多く含み、Colab のような特殊環境では失敗要素が多い

## 対処

- `run()` を Popen + PIPE で出力を Python 側で読み取り print する方式に変更。以後、コマンドの出力とエラーは必ずセルに表示される
- Ollama の導入を install.sh から公式の手動インストール手順に置き換え:
  `ollama-linux-amd64.tgz` をダウンロードして `/usr` に展開するだけ。環境検査なし。CUDA ランタイムは tgz に同梱されており、GPU ランタイムならそのまま GPU が使える
- ダウンロードは `wget --progress=dot:giga` にした。進捗が改行区切りで出るため、行単位ストリーミングと相性がよい

## 学び

- Colab でのサブプロセス実行は、出力を自前で読み取って print するのが確実。「動けば見える」を前提にしない
- 外部のインストールスクリプトは中身の検査項目まで含めて依存になる。展開するだけの手順があるならそちらを選ぶ

## 検証状況

- install.sh の失敗原因の特定は追わない（回避策で十分なため）
- 置き換え後の手順はまだ実機未検証。次回実行で確認する

# 追記: 2回目の実行 — .tgz が 404

回避策の `ollama-linux-amd64.tgz` も 404 で失敗した。run() の修正が効いて、今回は wget のログが全部セルに出た（リダイレクト先の GitHub リリース v0.32.6 に .tgz が存在しない）。

## 判明したこと

GitHub API でリリースのアセット一覧を確認したところ、Linux 向けの配布形式は **`.tar.zst`（zstd 圧縮）に変わっており、`.tgz` は廃止されていた**。公式 install.sh（リリース同梱版）を読むと:

- `.tar.zst` があればそれを使い、展開に `zstd` コマンドを要求する（なければ即エラー終了）
- 展開先は `/usr/local`（`bin/ollama` + `lib/ollama/` のレイアウト、CUDA ランタイム同梱）

初回の install.sh の exit 1 も、Colab に zstd がなかった可能性が高い（当時は出力が見えず確認できなかったが、この経路なら説明がつく）。

## 対処

- zstd がなければ `apt-get install zstd`
- `ollama-linux-amd64.tar.zst` を GitHub リリースの latest URL から取得し、install.sh と同じ `zstd -d | tar -x` で `/usr/local` へ展開
- 展開後に `ollama --version` を実行して導入を即確認する

## 学び

- 配布 URL・形式はリリースごとに変わりうる。外部リソースへの依存箇所は「今この瞬間の実物」を確認してから書く（今回は GitHub API と install.sh の実物で裏取りした）
