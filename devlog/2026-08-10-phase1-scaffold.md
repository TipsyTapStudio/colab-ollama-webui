## 設計上の判断

- **セルは `!` マジックを使わず純 Python（subprocess）で書いた。** 理由: (1) jupytext 変換時のマジック行エスケープ問題を避ける (2) 終了コードを検査して失敗時に例外で止められる（マジックは失敗しても次セルへ進めてしまう）
- **python3.11 は apt → 失敗時 deadsnakes PPA のフォールバック。** Colab の Ubuntu バージョンによって 3.11 が標準リポジトリにあるかが変わるため（22.04 なら universe にある、24.04 ならない）
- **ノートブックは自己完結にした（リポジトリの clone 不要）。** リポジトリ URL 確定前でも動かせるし、R4（セル実行だけで完結）にも沿う。フェーズ3の同期スクリプトを scripts/ に切り出す際に clone 方式へ変えるか再検討する
- **`.ipynb` は自作コンバータで生成。** 手元の Python は 3.14 のみで jupytext 未導入のため、依存なしで再現できる方が扱いやすい。セル id を決定的にして diff を安定させた
- **モデル自動選択の閾値**: VRAM ≥36GB → qwen3:32b / ≥20GB → qwen3:14b / ≥12GB → qwen3:8b / ≥6GB → qwen3:4b / それ未満（CPU）→ qwen3:0.6b
- **各セルが所要時間を print する。** AC6（起動時間）の実測データをフィードバックで集めるため
- **セルは冪等にした。** インストール済み・起動済みならスキップするので、途中で失敗しても上から再実行できる
- **停止セルは単独実行可能にした。** 再接続直後にカーネル変数（PROCS 等）が消えていても pkill で止められる
